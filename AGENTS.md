# flappy-haltere constraints

- This is a research harness, not a biological claim. Every haltere
  stimulation is host-side current injected before the connectome engine's
  kernel runs (in `connectome_sim/`) — an engineered joystick, not a measured
  reflex. Keep that distinction explicit in code comments and docs; don't
  describe an inferred/engineered mapping as validated biology.
- The inverse-dynamics model (`flappy/inverse_train.py`/`inverse_infer.py`)
  is trained on data generated by the real connectome simulation — treat that
  simulation as the oracle. When validating a model change, round-trip
  proposals back through the real simulation (GPU backend for frozen-weight
  runs) rather than trusting the model's own training-set performance alone.
- Every training run in `inverse_train.py` is a full retrain from scratch,
  never incremental — don't change that without flagging it, since results
  are compared against prior full-retrain baselines.
- Preserve failed/regressed experiments and their cause, not just current
  results — e.g. a training-data-gap regression on a specific cluster is
  worth a note even after it's fixed, since it explains why later training
  data was shaped the way it was.
- Do not modify `connectome_sim/`'s kernel or engine from this repo; that
  submodule is a separate repository with its own constraints. Bump the
  submodule pointer instead.
